Before you begin

This lesson continues 8 Basic Concepts of Programming in TLAC. You only need the ideas of a variable, a condition, a function, and a loop. We will use plain-language instruction cards to learn two new ideas.

  1. Recursion: a function calls itself to continue a job.
  2. Classes: describe a kind of object, with its own information and actions.

2. Now, with recursion

A loop says “do these instructions again.” A recursive function says “do one part, then call this same function for what remains.” Every safe recursive process needs a stopping case (often called the base case) and progress toward that case. The smaller job might be a shorter distance to a wall or fewer unvisited squares.

A definition does not move the turtle. It gives a group of instructions a name. In these recursive charts, begin with the main instructions after the function definitions. A call enters the named function. A call from inside that same function is recursion. Calling a different helper function is an ordinary function call.

Three different ways to stop: “Return” ends only the current function call and resumes after the call that started it. “Leave the innermost loop” exits only that loop. “End Program” stops everything. In the supplied programs, loop-exit or return instructions immediately after End Program are not reached.

Follow the calls: two spaces from a wall

Imagine goToBeginningOfBoard starting two spaces from the wall. Each call keeps a bookmark saying where to continue when its helper finishes. A new call uses the same instructions, but the turtle’s position has already changed.

  1. Call A: 2 spaces remain → move 1 space → call B; A waits.
  2. Call B: 1 space remains → move 1 space → call C; B waits.
  3. Call C: at the wall → cannot move → return to B. This is the base case.
  4. B has nothing left to do → return to A. A also finishes → return to the main instructions.

These waiting calls form a call stack: the last call started is the first to finish. Returning does not undo a move; the turtle stays at the wall. For the board game, put each return bookmark on a small pile of paper slips, and remove the top slip when returning.

Which should you choose? For a simple repeated movement, a loop is often easier to follow. Recursion is useful when the remaining work naturally resembles the original job. Each unfinished call needs a return bookmark, so very deep recursion can use too much memory. These examples teach the idea; recursion does not automatically make a program faster.

3. Classes and objects

A class describes a kind of thing: the information it keeps and the actions it can perform. Here our class describes a turtle. An object is one particular turtle made from that description, also called an instance. Aki and Sol can be two objects of the same Turtle class.

Class: Turtle

  1. Attributes (stored information): name, horizontal position X, vertical position Y, and direction.
  2. Constructor (initial setup): receive a name and starting X and Y; create this turtle there, facing up.
  3. Method “Move forward”: move this turtle one square in its own direction.
  4. Method “Turn right”: rotate this turtle 90° clockwise; its position stays the same.
  5. Method “Place an egg”: place an egg on this turtle’s current square.
  6. Method “Mark and move”: ask this turtle to place an egg, then ask it to move forward. One method can use other methods.

An attribute is a named piece of information belonging to an object. A method is a function provided by its class. “This turtle” means the object receiving the request: asking Aki to move changes Aki’s position. The class definition alone does not create a turtle or move it. Creating an object runs its constructor, not all of its methods.

These examples use a 6 × 6 TLAC board. X increases to the right; Y increases downward. The top-left square is X=0, Y=0. The paths below stay inside the board. The full executions show every method request and the individual turtle actions it causes.

Example 1: one turtle leaves an egg trail

Create Aki at X=1, Y=4, facing up. Ask Aki to mark and move twice, turn right, and mark and move once more. The two upward moves change Y from 4 to 2. The final move changes X from 1 to 2. Aki finishes at X=2, Y=2, facing right, with three eggs left behind.

Example 2: two objects, independent positions

Start a fresh board. Create Aki at X=1, Y=4 and Sol at X=4, Y=4. Both face up. Ask Aki to mark and move twice. Sol has not moved! Now ask Sol to turn right and mark and move once. Aki stays at X=1, Y=2, facing up; Sol finishes at X=5, Y=4, facing right.

Same class, separate state. Aki and Sol use the same methods, but each stores its own name, X, Y, and direction. They share the board, so both can see eggs placed on it. An egg belongs to a board square, not to the turtle’s personal attributes. The execution page lists both turtles’ states so you can see which one changes.

Calling “Mark and move” uses other methods, but it is not recursion: that method never calls itself. Classes organize information and actions. Recursion is a way for a function to repeat work. A method can be recursive, but it does not have to be.

4. Try it yourself

1. What if the move toward the wall is removed?

Show an answer

If the turtle starts away from the wall, the next call sees the same position. It keeps calling without reaching the base case. A stopping condition alone is not enough: the repeated action must make progress.

2. Does returning from the column-filling function end the entire program?

Show an answer

No. Return resumes the caller. That caller may turn the turtle and start another column. End Program is the instruction that stops everything.

3. Aki and Sol face up. Ask only Sol to turn right. Does Aki turn too?

Show an answer

No. Sol faces right; Aki still faces up. Each turtle object stores its own direction attribute.

4. Design a “Turn around” method for the Turtle class.

Show an answer

Ask this turtle to turn right twice. Its direction changes by 180°, while X and Y stay unchanged. Another turtle on the board should keep its own direction.

Remember: recursion needs a stopping case and progress toward it. A class describes attributes and methods; each object has its own state. You can trace both ideas with paper, coins, and a few instruction cards.

2. Ahora, con recursión

Un bucle dice «haz estas instrucciones otra vez». Una función recursiva dice «haz una parte y llama a esta misma función para lo que falta». Todo proceso recursivo que deba terminar necesita un caso de parada (o caso base) y avanzar hacia él. La tarea restante puede ser una distancia menor hasta una pared o menos casillas sin visitar.

Una definición no mueve la tortuga. Da un nombre a un grupo de instrucciones. En estas tarjetas recursivas, empieza por las instrucciones principales que vienen después de las definiciones. Una llamada entra en la función indicada. Si una función se llama a sí misma, hay recursión. Llamar a otra función auxiliar es una llamada normal.

Tres formas distintas de parar: «Volver» termina solo la llamada actual y continúa después de la llamada que la inició. «Salir del bucle más interno» sale solo de ese bucle. «Terminar programa» lo detiene todo. En los programas proporcionados, las instrucciones de salir del bucle o volver que siguen inmediatamente a Terminar programa no se ejecutan.

Sigue las llamadas: a dos casillas de una pared

Imagina que goToBeginningOfBoard empieza a dos casillas de la pared. Cada llamada guarda un marcador que indica dónde continuar cuando termine la llamada que hace. La nueva llamada usa las mismas instrucciones, pero la posición de la tortuga ya ha cambiado.

  1. Llamada A: faltan 2 casillas → avanzar 1 → llamar a B; A espera.
  2. Llamada B: falta 1 casilla → avanzar 1 → llamar a C; B espera.
  3. Llamada C: está en la pared → no puede avanzar → volver a B. Este es el caso base.
  4. A B no le queda nada por hacer → vuelve a A. A también termina → vuelve a las instrucciones principales.

Estas llamadas en espera forman una pila de llamadas: la última que empieza es la primera que termina. Volver no deshace los movimientos; la tortuga se queda en la pared. Para jugar en papel, apila papelitos con el lugar al que debes volver y retira el de arriba al regresar.

3. Clases y objetos

Una clase describe un tipo de cosa: la información que guarda y las acciones que puede realizar. Aquí la clase describe una tortuga. Un objeto es una tortuga concreta creada a partir de esa descripción; también se llama instancia. Aki y Sol pueden ser dos objetos de la misma clase Tortuga.

Clase: Tortuga

  1. Atributos (información guardada): nombre, posición horizontal X, posición vertical Y y dirección.
  2. Constructor (preparación inicial): recibir un nombre y las coordenadas X e Y; crear esta tortuga allí, mirando hacia arriba.
  3. Método «Avanzar»: mover esta tortuga una casilla en su propia dirección.
  4. Método «Girar a la derecha»: girar esta tortuga 90° en sentido horario; su posición no cambia.
  5. Método «Poner un huevo»: poner un huevo en la casilla actual de esta tortuga.
  6. Método «Marcar y avanzar»: pedir a esta tortuga que ponga un huevo y luego que avance. Un método puede usar otros métodos.

Un atributo es un dato con nombre que pertenece a un objeto. Un método es una función que proporciona su clase. «Esta tortuga» es el objeto que recibe la petición: pedir a Aki que avance cambia la posición de Aki. La definición de la clase por sí sola no crea ni mueve una tortuga. Crear un objeto ejecuta su constructor, no todos sus métodos.

Estos ejemplos usan un tablero TLAC de 6 × 6. X aumenta hacia la derecha; Y aumenta hacia abajo. La esquina superior izquierda es X=0, Y=0. Los recorridos se mantienen dentro del tablero. Las ejecuciones completas muestran cada petición a un método y las acciones de la tortuga que provoca.

Ejemplo 1: una tortuga deja un rastro de huevos

Crea Aki en X=1, Y=4, mirando hacia arriba. Pídele que marque y avance dos veces, gire a la derecha y marque y avance una vez más. Los dos movimientos hacia arriba cambian Y de 4 a 2. El último movimiento cambia X de 1 a 2. Aki termina en X=2, Y=2, mirando a la derecha, con tres huevos detrás.

Un huevo pertenece a una casilla, no a los atributos personales de una tortuga. La página de ejecución muestra los estados de ambas para ver cuál cambia.

«Marcar y avanzar» usa otros métodos, pero no es recursión: ese método nunca se llama a sí mismo. Las clases organizan información y acciones. La recursión permite que una función repita trabajo. Un método puede ser recursivo, pero no tiene por qué serlo.

4. Practícalo

1. ¿Qué pasa si se quita el movimiento hacia la pared?

Mostrar una respuesta

Si la tortuga empieza lejos de la pared, la siguiente llamada ve la misma posición. Sigue llamando sin alcanzar el caso base. No basta con una condición de parada: la acción repetida debe avanzar hacia ella.

2. ¿Volver desde la función que llena una columna termina todo el programa?

Mostrar una respuesta

No. Volver reanuda la función que hizo la llamada. Esta puede girar la tortuga y empezar otra columna. Terminar programa es la instrucción que lo detiene todo.

3. Aki y Sol miran hacia arriba. Pide solo a Sol que gire a la derecha. ¿Gira también Aki?

Mostrar una respuesta

No. Sol mira a la derecha; Aki sigue mirando hacia arriba. Cada objeto tortuga guarda su propio atributo de dirección.

4. Diseña un método «Dar media vuelta» para la clase Tortuga.

Mostrar una respuesta

Pide a esta tortuga que gire a la derecha dos veces. Su dirección cambia 180°, mientras X e Y no cambian. Otra tortuga del tablero debe conservar su dirección.

Recuerda: la recursión necesita un caso de parada y avanzar hacia él. Una clase describe atributos y métodos; cada objeto tiene su propio estado. Puedes seguir ambas ideas con papel, monedas y unas tarjetas de instrucciones.

はじめに

この教材はTLACで学ぶプログラミングの8つの基本概念の続きです。変数、条件、関数、繰り返しがわかれば始められます。わかりやすい言葉で書かれた命令カードで、2つの新しい考え方を学びましょう。

  1. 再帰：関数が自分自身を呼び出して仕事を続けます。
  2. クラス：情報と動作をまとめて、どのようなオブジェクトを作るかを決めます。

TLACカードの読み方。青い数字は命令の位置、黄色いカードは命令、緑のカードは読む人のためのコメントです。囲みは、ひとまとまりの命令を表します。コインで現在の命令を指しながら読んでみましょう。距離の指定がなければ1マス進み、回転は90度です。卵を置くと、今いるマスに印がつきます。

以下の問題4〜8では、元のプログラムの順番と条件分岐を保っています。それぞれの初期位置と盤面を想定した例であり、どんな迷路でも解けるわけではありません。卵は通ったマスの印です。2マス進む命令は2マス先を移動先とし、これらの例は途中に障害物がないことを想定しています。

各プログラムの後に、最初と最後の盤面があります。実行結果へのリンクを開き、「次へ」「前へ」で命令、動作、関数からの戻りを追いましょう。すべてのステップを展開して、盤面をまとめて見ることもできます。命令番号はプログラムのカードと対応しています。亀の真下の卵は絵では隠れますが、卵の数には含まれます。

2. 次は再帰を使って

繰り返しは「この命令をもう一度行う」という方法です。再帰関数は「仕事を一部分だけ行い、残りを同じ関数に任せる」という方法です。終了する再帰処理には、止まる場合（基底ケース）と、そこへ近づく変化が必要です。残りの仕事が小さくなるとは、壁までの距離が短くなったり、まだ通っていないマスが減ったりすることです。

関数を定義するだけでは、亀は動きません。命令のまとまりに名前をつけるだけです。この再帰の図では、関数定義の後にあるメインの命令から実行を始めます。呼び出しでその関数の中へ入り、その関数自身を中から呼ぶと再帰になります。別の補助関数を呼ぶだけなら、普通の関数呼び出しです。

3種類の「終わる」を区別しましょう。「戻る」は今の関数呼び出しだけを終え、呼び出し元の次の命令から続けます。「一番内側の繰り返しから抜ける」は、その繰り返しだけを終えます。「プログラム終了」は全体を止めます。元のプログラムでは、その直後にある「抜ける」や「戻る」の命令には到達しません。

呼び出しを追う：壁まであと2マス

壁まであと2マスの位置でgoToBeginningOfBoardを呼んだとします。呼び出すたびに、終わった後に続ける位置をしおりのように覚えておきます。新しい呼び出しも同じ命令を使いますが、亀の位置はすでに変わっています。

  1. 呼び出しA：残り2マス → 1マス進む → Bを呼ぶ。Aは待つ。
  2. 呼び出しB：残り1マス → 1マス進む → Cを呼ぶ。Bは待つ。
  3. 呼び出しC：壁に着いた → 進めない → Bへ戻る。これが基底ケース。
  4. Bにはもう仕事がない → Aへ戻る。Aも終わる → メインの命令へ戻る。

待っている呼び出しはコールスタックを作ります。最後に始めた呼び出しから先に終わります。戻っても移動は取り消されず、亀は壁のところにいます。紙で遊ぶなら、戻る位置を書いた紙を積み、戻るときに一番上の紙を取りましょう。

3. クラスとオブジェクト

クラスは、ある種類のものについて「どんな情報を持つか」「何ができるか」を決める説明書です。ここでは亀のクラスを作ります。オブジェクトは、この説明書をもとに作る1匹ずつの亀で、インスタンスとも呼びます。AkiとSolは、同じ亀クラスから作った別々のオブジェクトです。

クラス：亀

  1. 属性（保存する情報）：名前、横の位置X、縦の位置Y、向き。
  2. コンストラクター（最初の準備）：名前と開始位置X、Yを受け取り、そこに上向きの亀を作る。
  3. メソッド「前に進む」：この亀を、この亀が向いている方向に1マス進める。
  4. メソッド「右に回る」：この亀を時計回りに90度回す。位置は変えない。
  5. メソッド「卵を置く」：この亀が今いるマスに卵を置く。
  6. メソッド「卵を置いて進む」：この亀に卵を置かせてから前に進ませる。メソッドは他のメソッドを使うこともできる。

属性はオブジェクトが持つ名前つきの情報です。メソッドはクラスが提供する関数です。「この亀」は動作を頼まれたオブジェクトを指します。Akiに進むよう頼むと、Akiの位置が変わります。クラスを定義するだけでは亀は作られず、動きもしません。オブジェクトを作るとコンストラクターを実行しますが、すべてのメソッドを実行するわけではありません。

この例では6×6のTLAC盤面を使います。Xは右へ、Yは下へ進むほど大きくなります。左上はX=0、Y=0です。以下の経路は盤面の内側に収まります。実行結果では、メソッドへのお願いと、その中で起きる亀の動作を1つずつ確認できます。

例1：1匹の亀で卵の道を作る

X=1、Y=4に上向きのAkiを作ります。「卵を置いて進む」を2回頼み、右に回ってから、もう一度「卵を置いて進む」を頼みます。上への2回の移動でYは4から2になり、最後の移動でXは1から2になります。AkiはX=2、Y=2で右を向き、通った場所には3個の卵が残ります。

実行結果を開く：すべての命令と盤面 →

例2：2つのオブジェクト、それぞれの位置

新しい盤面で始めます。X=1、Y=4にAkiを、X=4、Y=4にSolを作ります。両方とも上向きです。Akiに「卵を置いて進む」を2回頼んでも、Solは動きません。次にSolに右へ回ってから「卵を置いて進む」を1回頼みます。AkiはX=1、Y=2で上向きのまま、SolはX=5、Y=4で右向きになります。

同じクラスでも、状態は別々です。AkiとSolは同じメソッドを使いますが、名前、X、Y、向きはそれぞれが持っています。盤面は共有するので、置かれた卵は両方の亀から見えます。卵はマスにあるもので、亀自身の属性ではありません。実行結果に両方の亀の状態が表示されるので、どちらが変わったか確認しましょう。

「卵を置いて進む」は他のメソッドを使いますが、自分自身を呼ばないので再帰ではありません。クラスは情報と動作をまとめ、再帰は関数が仕事を繰り返す方法です。メソッドで再帰を使うこともできますが、必ず使う必要はありません。

4. 練習してみよう

1. 壁へ近づく移動を消すとどうなる？

答えを見る

壁から離れた位置で始めると、次の呼び出しでも位置は同じです。基底ケースに達せず、呼び出しを続けてしまいます。停止条件があるだけでは足りず、そこへ近づく動作が必要です。

2. 列を埋める関数から戻ると、プログラム全体が終わる？

答えを見る

いいえ。呼び出し元に戻って続けます。呼び出し元は亀の向きを変えて次の列を始めることもあります。全体を止めるのは「プログラム終了」です。

3. AkiもSolも上向きです。Solだけに右へ回るよう頼むと、Akiも回る？

答えを見る

いいえ。Solは右向きになりますが、Akiは上向きのままです。それぞれの亀オブジェクトが自分の向きを持っているからです。

4. 亀クラスの「反対を向く」メソッドを考えよう。

答えを見る

この亀に右へ回るよう2回頼みます。向きは180度変わりますが、XとYは変わりません。盤面にいる他の亀の向きも変わりません。

覚えておこう：再帰には停止条件と、そこへ近づく変化が必要です。クラスは属性とメソッドを決め、各オブジェクトは自分の状態を持ちます。紙とコイン、そして命令カードで、どちらの仕組みもたどることができます。
